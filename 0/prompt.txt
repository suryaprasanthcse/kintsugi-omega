## 7. Execution protocol (binding)

Batching:
- Batch independent Read/Grep/Glob and read-only Bash calls in ONE message.
- Edits for one commit to DIFFERENT files may be batched. Never batch two edits to the same file, and never batch an edit with a commit.
- Graph first (`entire graph search --repo . --profile full --query "…"`), then line ranges. Never read the spec or the plan whole.

Background:
- Run rehearsals, the full suite and CI with run_in_background, plus ONE Monitor or until-wait whose filter covers every terminal state: DONE|Traceback|Error:|FAILED|passed in|failed in. Never `until grep error`: pyright prints "0 errors".
- While a job runs: read, design, or write outside the repo only.
- Never commit while a background job writes into the working tree, and never start one with uncommitted edits.

Commits (A-16, A-37):
- Every tracked change goes through Edit or Write. Shell rewrites (sed, ruff --fix, ruff format) only on files Edit/Write also touched in the same commit.
- Before the first edit of commit N+1, commit N with EVERY edited file, so `git status -s` is empty.
- Commit with ENTIRE_TEST_TTY=0. Verify after every commit:
~~~bash
ID=$(git log -1 --format='%(trailers:key=Entire-Checkpoint,valueonly)'); git show-ref | grep -c "$ID"; uv run python -I -c "from kintsugi.memory import entire; import subprocess; t=set(entire.read_checkpoint('.', '$ID').metadata.get('files_touched') or []); d=set(subprocess.run(['git','show','--name-only','--format=','HEAD'],capture_output=True,text=True).stdout.split()); print('missing from files_touched:', sorted(d-t))"
~~~
- Acceptable "missing" entries: only declared tool-written files (A-1). Anything else: stop and fix.
- After an involuntary turn end, the FIRST action of the next turn is to commit exactly the pending files.

Lanes (D8):
- One Claude session writes to the repo.
- Rehearsals and the runtime write outside it; their artifacts enter only as declared copies (A-1).
- The Architect's custody actions run in his own terminal. No subagents for writing.

Tests (anti-redundancy):
- Per commit: targeted tests only. Test modules of touched packages plus dependents found with `entire graph impact --repo . --symbol X`. Add tests/control when control/ changes; add real-eval crew/gates tests only when crew/, gates/ or fleet/ change.
- Per stage: run the full suite (about 14 min) EXACTLY ONCE, in the background, on the final code HEAD that will be pushed. Later commits may only touch *.md that no test reads, or declared evidence.
- After `git push`: watch omega-ci once with `gh run watch <id> --exit-status` in the background. NEVER re-run the full suite locally after the push.
- Never re-run a passing gate or rehearsal to "confirm". Record every run, failures included, in docs/VERIFICATION.md.

Push:
- Secret-scan ONLY the refs being pushed: `redaction.assert_pushable('.', new_refs)`.
- Never chain a ref sync after a failed scan with ';'.
- `scan_refs('.')` over ALL refs reports 14 known false positives: the OpenSSH header literal in a Stage 1 test assertion, in refs public since Oct 11.

Quota (get_usage at start, before every rehearsal, at every commit):

- 70–85%: finish the current commit; start no rehearsal (crew calls share the quota).
- ≥ 85%: commit, stop editing, write a resume note in memory, wait for the reset (17:50 IST, then about 22:50 IST).
